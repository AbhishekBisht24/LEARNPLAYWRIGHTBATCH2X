## 📝 Key Concepts Summary

### Identifier Rules
- Must start with a letter, underscore (_), or dollar sign ($)
- Can contain letters, digits, underscores, and dollar signs
- Are case-sensitive (name ≠ Name)
- Cannot be reserved words (const, let, var, function, etc.)

### Naming Conventions
- **camelCase:** Variables and functions (myVariable, myFunction)
- **PascalCase:** Classes and constructors (MyClass, MyConstructor)
- **UPPER_SNAKE_CASE:** Constants (MAX_ATTEMPTS, API_KEY)

### Literals
- **String Literals:** 'text', "text", `text`
- **Number Literals:** 42, 3.14, 0xFF
- **Boolean Literals:** true, false
- **Array Literals:** [1, 2, 3]
- **Object Literals:** {name: 'John', age: 30}

### Comments
- **Single-line:** // This is a comment
- **Multi-line:** /* This is a multi-line comment */
- **JSDoc:** /** Documentation comment */

## 💡 Tips

- **For Identifiers:**
  - Choose descriptive names that explain purpose
  - Avoid single-letter variables (except in loops)
  - Use camelCase for variables and functions consistently
  - Avoid abbreviations unless widely known

- **For Comments:**
  - Comment "why" not "what" - code shows what, comments explain why
  - Keep comments updated with code changes
  - Use JSDoc for functions and classes
  - Don't over-comment obvious code

## ❓ Common Questions

**Q: Which naming convention should I use?**
A: Use camelCase for variables/functions, PascalCase for classes, UPPER_CASE for constants.

**Q: How many comments should I write?**
A: Comment complex logic, not every line. Aim for 1 comment per 5-10 lines of code.

**Q: Why does naming matter?**
A: Good naming makes code self-documenting and easier for others (and future you) to understand.
